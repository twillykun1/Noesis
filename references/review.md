# 关键节点与独立复核

## 触发
高后果（数据、权限、核心承诺）、难以恢复、关键事实未证实且即将扩散到多个依赖、越过既有范围、重要新证据推翻前提。风险不按平均分抵消。

先说清：这一步会影响什么；哪个前提未知/改变了；越过哪一步后纠正代价变大。

## 匹配手段
- 缺事实：查代码、日志、契约或用户目标。
- 缺验证：最小复现、边界测试、负载实验或受控试用。
- 有实质争议或高后果复杂权衡：独立评审加证据核验。
- 只是实现偏好且可逆：正常执行，不升级成委员会。

## 评审协议（不内置调用器）
主 agent 核实当前可用工具、用户权限和数据边界后，按需要安排少量独立评审，不默认无限扩展成本。可以分别审查目标/影响、实现/故障、验证/可逆性。多角色可发现不同问题，但不等于不同模型或统计独立。

给每位评审同一份问题、事实与缺口、约束、候选方案。候选中包含原方案，但不要用“大家都同意”等暗示。先不提供其他评审结论。

请求输出：
1. 建议与证据；
2. 最有影响的错误前提或反例；
3. 什么观察能推翻该建议；
4. 最小验证；
5. 确定性限制。

汇总事实分歧、价值取舍和实现分歧，保留实质少数意见。计票不能证明事实。能查证就查证，需用户设定价值边界才提问。无法消除的重要未知应显式保留，暂停依赖该未知的不可逆步骤；不把沉默或模型共识视为授权。

只有一个模型时，可做角色化自查并标为单模型自查。工具不可用时，不声称运行过外部模型。不自动把代码、日志或用户对话发到第三方服务。

复核结论只能建议；实际强制门禁依靠宿主权限、仓库保护和执行系统。Markdown skill 无法保证每轮都运行或阻止所有越界工具调用。

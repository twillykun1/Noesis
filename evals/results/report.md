## 基线先行

编写 SKILL.md 前，独立上下文评估了 A/B/C、D 和贡献复盘，共五个场景输出（分三个调用，非五次重复）。原文保留于 baseline-*.md。

- A/B/C 已能识别超时副作用、保持简单文案修改轻量、关注缓存新鲜度。
- D 已能更新决定、保留历史、限定旧版本测试证据。
- 贡献复盘已能避免夸大避免损失，并识别 def 未测。
- 因此没有证据声称本 skill 新增了上述基础能力。
- 相对于完整决策闭环目标，D 的基线没有明确记录可观察的“何时重新打开这项决定”。此为本次关注的结构缺口，不是安全失败，也不表示基线模型不会做。

## 加载后模拟

加载 SKILL.md 后独立上下文运行四个场景，原文见 with-skill.md。搜索约束变更与文案场景对应基线类型，删表场景为新增压力案例；提示措辞并非完全相同，不能视为严格 A/B 因果比较。

观察：
- 搜索变更记录包含计划差异、验收版本和明确重开条件，并区分测试人数与并发量。
- 文案修改保持简短，没有多评审或强制决策卡。
- 删表没有以三模型一致替代依赖/恢复证据，也未假称线上访问。
- 复盘保持证据版本约束，未虚构损失数字。

发现的局限：
- 重要事项的“回复 + 完整记录”存在内容重复；真实使用应只在需要持久化时保存完整卡，消息只呈现关键变化。当前结构允许但仍需真人检验负担。
- 测试提示中的英文 staging 引起额外语义澄清，说明混合术语本身会引入不必要负担。未来试验应使用一致、自然的用户原话，避免把提示差异当 skill 效果。
- 一次输出不能证明稳定性或能力提升。不同 agent 不等于不同模型；未做跨模型对照。

## 检查边界

已运行官方 skill frontmatter 校验；另检查相对链接、UTF-8、必需文件和 ZIP 完整性。结构通过不证明行为有效。

本次未完成每变体五次以上新上下文盲评、重复压力测试、真实用户测试、跨领域迁移、自动触发和宿主端到端测试。初版可手动试用，不应作为高风险执行门禁上线。

## 下一轮优先项

1. 固定完全一致的提示，对“重开条件”和“响应冗余”做多次盲评。
2. 用真实开发记录测试：用户离开后回来，能否恢复背景并纠正错误前提。
3. 分别评估理解、取舍质量与时间负担，不合并成虚构总分。
4. 有足够证据后再决定 UI、多模型调用器和持续触发机制，而非先增加系统复杂度。

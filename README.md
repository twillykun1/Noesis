# Noesis

**简体中文** | [English](README.en.md)

**Understand the work. Own the decision.**

让 AI 把代码行为讲成你能判断的现实后果，并把你的决定落实到交付。

你有开发经验，却不可能熟悉每个技术领域。Noesis 帮你在跨领域开发时掌握方向、关键风险和验收；AI 负责调查、给出建议、实现与验证。只补充影响选择的必要背景，已授权的工作继续推进。

## 从“参数怎么选”到“这会影响谁”

例如，你想让商品接口更快：

| 只讨论实现参数 | 用 Noesis 追踪项目后果 |
| --- | --- |
| “加 60 秒缓存，你能接受多久延迟？” | “若检查发现结算也读取这个接口，缓存可能让客户按旧价格付款。我会先确认瓶颈与调用链，再建议如何提速并保持结算准确。” |

后续建议会带上实际证据、代价和失效前提；你的选择会变成工程约束和验收条件。以上是协作示例，不是效果测试结果。

## 一句话安装

把这句话交给你的 AI：

> 请使用你内置的 skill-installer，从 https://github.com/twillykun1/Noesis/tree/main/skills/noesis 安装 Noesis；若已安装，先说明差异再更新。

优先使用 Codex 官方 `skill-installer`，安装路径是 `skills/noesis`，不是仓库根目录。已有版本先比较、备份，在取得替换授权后更新；这句话是更新流程要求，**不是自动更新器**。安装位置和重新加载方式以宿主说明为准。

## 开始使用

> 使用 Noesis 帮我改造登录会话。先检查现状，说明关键取舍的实际影响；已授权的工作继续推进。

也可以直接说：“不懂”“不同意”“过细”“没必要”。AI 应调整表达；如果反馈改变了目标或限制，也应调整方案、实现和验收。普通文案修改直接完成，无需新增决策文档。

## 它怎么工作

- **从目标出发**：先弄清希望谁的体验或工作发生什么变化。
- **沿代码看后果**：检查相关配置、调用者与消费者，把系统行为连接到业务动作和受影响的人。
- **带着依据建议**：区分事实、推断和偏好，说清收益、代价及哪些前提变化会使建议失效。
- **让决定落地**：将重要选择关联到工程约束、实现与可观察的验收，区分“做了”和“验证了”。

核心指令保持轻量。复杂任务按需读取跨模块调查指导；重要状态优先更新已有计划或 ADR，不为每个任务另建表格。

## 解释偏好与保存位置

偏好是默认，不是固定模板：讲法还要结合当前目的、已展现的知识和即时反馈。卡在抽象处可以用贴近问题的例子；已经理解的背景或无帮助的比喻就跳过。不把用户归为固定“学习类型”。

在支持用户级指令的 Codex 环境，默认私有记录是 `~/.codex/AGENTS.md` 的 `Noesis communication preferences` 小节；设置 `CODEX_HOME` 时使用该目录。已有 `AGENTS.override.md` 可能遮蔽它。个人偏好不进入本仓库或技能安装包；其他宿主须有自己的可靠私有存储，否则仅限当前对话。详见 [具体路径与读取边界](docs/maintenance.md#codex-保存到哪里下次怎么读) 和 [运行时存储指导](skills/noesis/references/preferences.md)。

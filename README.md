# Noesis · v0.1.0

**Understand the work. Own the decision.**

看懂关键取舍，让决定约束执行，让结果反过来改善判断。

面向 AI 辅助软件开发的通用 skill 初稿：适用于 bug 修复、功能开发和架构取舍，不依赖某个人的职业、兴趣或熟悉的产品。当前范围先限定软件开发，不声称已经泛化到所有领域。

## 为什么做

AI 报告经常只有事实或技术结论，用户要自己找背景、拼因果、记状态。单纯要求用户确认或复述，只会把负担推回去。本项目先降低理解与核验成本，再帮助形成有依据的决定。

决策质量是目标；减少认知负担、提高决策能力、增加参与感都不是它的替代指标。

## 核心闭环

背景与事件 → 证据支持的判断 → 建议及代价 → 必要的人的输入 → 实际计划差异 → 验证 → 新证据下重开。

- 普通低风险修改：轻量执行，不新增审批会议。
- 关键取舍：展示影响、可逆性、未知和依赖；不以代码行数判重要性。
- 人的意见：真实更新计划/范围/验收，或如实记录确认现有方向。
- 持续质疑：检查人和 AI 的假设；只在有实质新依据时重新打断。
- 多模型：可选评审协议，不按票数决定，也不自带模型 API。
- 决策记录：当前状态与历史分开，接受、实现、验证分别记录。

## 快速试用

这是可携带的 skill 目录，不会自动安装、启用监控或调用其他模型。

1. 解压，保留整个 `noesis/` 文件夹及相对路径。
2. 在支持文件读取的 agent 中，明确要求读取并遵循 `noesis/SKILL.md`，然后给一个真实开发任务。
3. 若宿主支持标准技能目录，可将整个目录放入其技能位置。Codex 的常见目录是 `${CODEX_HOME:-$HOME/.codex}/skills/`；具体发现/重新加载方式以宿主为准。本包未在你的本地环境安装或做加载测试。
4. 不支持自动技能发现时，把 SKILL.md 作为任务指令提供，参考文件按需附上；这是手动使用，不等同原生插件。

可用试用请求：
> 请读取 noesis/SKILL.md，协助评估一个查询接口的缓存方案。当前 p95 为 900ms，目标 200ms，尚未定位瓶颈，价格数据的允许延迟还没确定。先帮助我理解取舍，不要直接修改代码。

模型需要保留用户语言；核心指令使用英文以便不同 agent 读取，说明和示例使用中文。

## 文件导航

- `SKILL.md`：运行时核心指令，按需读取其他文件。
- `DESIGN.md`：整体设计、取舍与后续验证方向。
- `references/review.md`：关键节点、独立复核与无多模型能力时的降级。
- `references/research.md`：研究依据及外推限制。
- `templates/decision-record.md`：可选决策记录，可接入既有 ADR/issue。
- `examples/scenarios.md`：跨任务、不同风险级别的对比例子。
- `evals/README.md`：对照评测方法、案例和人工评分规则。
- `evals/results/`：本次有限模拟的原始输出与结论。

## 初版明确不做

不建设看板 UI；不安装 hook；不监听用户；不评估用户智力/掌握程度；不对每轮“继续”强制提问；不把 agent 多开冒称不同模型；不越过宿主权限或仓库工程规范。未来 UI 应消费同一决策记录，而不是形成另一个与真实代码脱节的审批系统。

Markdown skill 无法保证每轮触发或硬阻断操作。强约束必须由宿主执行控制和仓库规则实现。保存决策只限当前任务授权范围，不跨项目收集对话或秘密。

## 验证状态

已提供本地结构检查和少量独立上下文模拟；详见评测报告。未开展正式多次盲测、真实用户试验、跨基础模型对照或宿主端到端加载测试。因此不能宣称提升了真实决策质量或已达到生产发布标准。

本项目暂未附带开源许可证；公开可见不等于授予开源使用许可。许可证和贡献规范将在后续明确。v0.1 的重点是可试用、可评估、可迭代。
